# Matusiak bowed-string friction

This method implements Matusiak, Chatziioannou and Van Walstijn, [“Numerical modelling of elasto-plastic friction in bow–string interaction with guaranteed passivity”](https://doi.org/10.3389/frsip.2025.1525044), Frontiers in Signal Processing, 2025.
It includes the complete finite-width bow model with transverse stiff-string motion, torsional motion, compliant bow hair, and implicit elasto-plastic friction.
The native FP64 result is checked against the actual authors' MATLAB computation executed in GNU Octave.
Metal 4 provides complete independent string trajectories in parallel and the paper's lumped bowed-mass model.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target MatusiakTest matusiakReproduce -j8
build/MatusiakTest
python3 tools/matusiak_reproduce.py --binary build/matusiakReproduce
```

Use `--offline` with downloaded references and `--author-reference` to regenerate the original and corrected author computations with `octave-cli`.
The committed numeric fixture supports the native test without MATLAB or Octave.
Use `--gpu-voices 0` for CPU-only reproduction or change the default 128-voice GPU comparison batch.
Outputs are WAVs, a compact manifest, and listening cases under `outputs/reproduction/matusiak/`.
`bridge_force.wav` retains force in newtons; `bridge_listening.wav` applies one recorded gain for listening.

## Author reference and conventions

The paper links [Zenodo 15341818](https://doi.org/10.5281/zenodo.15341818), whose versioned release is [15341819](https://zenodo.org/records/15341819).
The corresponding [author repository](https://github.com/wasilakis/the_bowed_string/tree/1.0) is pinned to `0e2d39d0d62460370f1de3945a4f1a2c984b038c`.
The later upstream main revision `3c29a71bcd3b35891710b4e4642c31ec7a1be11d` was also inspected and adds no excitation recordings or cello impulse response; its changed late-Newton damping is outside this pinned reproduction.
The source is GPL-3.0; its license is retained in `src/matusiak/LICENSE` and the downloaded reference checkout.
This implementation follows the equations and that archived implementation; the source and fixture hashes are in `repros/matusiak/Reference.json`.
The fixture contains the complete 22050-sample original and corrected outputs, generated by GNU Octave 11.3.0 with unchanged computation arithmetic, excluding plotting.

The reproduced case uses the code's defaults, which differ from rounded paper Table 2 values:

| Quantity | Author code convention retained |
|---|---|
| Duration and rate | 0.5 s, 44100 Hz, initial zero sample |
| String | Length 0.7 m, radius 0.0005 m, fundamental 98 Hz, tension 149.7415 N, Young modulus 1.37e10 Pa |
| Transverse loss | 1.53714 /s and 0.0087 m²/s |
| Torsion | Stiffness 3.0312e-4 N m², polar inertia 4.2e-10 kg m, damping 1/58 /s |
| Bow | 2.3433 N, 0.3439 m/s, acceleration 0.8722 m/s², width 0.01 m, position 0.0786 L |
| Bow hair | 0.0045 kg, 48297 N/m, 5.7674 kg/s, each divided by bow width |
| Friction | Stiffness 318600, damping 0.0027, Stribeck velocity 0.228 m/s, dynamic/static coefficients 0.5071/1.0207 |
| Contacts | The source's requested four subdivisions produce five inclusive endpoints |
| Breakaway | 0.7 times dynamic-friction steady bristle deflection |
| Interpolation | Cubic author stencil and author interior-array indexing |

The string density is derived from tension and `c=2Lf0`, as in the source.
The source treats the listed bow force as the total force and divides its interaction over the contact count, despite the paper table's N/m label.
Its cubic interpolation treats the first interior degree of freedom as coordinate zero, producing an approximately one-grid-cell location offset; that indexing is retained to make comparisons reproducible.
The resulting grids have 158 transverse intervals and 36 torsional intervals at 44100 Hz.
The bow-velocity ramp includes both endpoints and uses `ceil(v/a * fs)` samples.

One source discrepancy is corrected explicitly: the final bow-hair term of `IJ_mat` adds a scalar to every matrix entry, whereas Equation 59 requires that scalar times the identity.
The native solver uses the equation's diagonal compliance.
Two actual author outputs are retained: the unchanged original and a run changing only that term to `1/M * 1/O3 * eye(M)`.
For the original default run, the final assumed versus reconstructed slip velocities differ by about 4.38e-5 m/s, while the diagonal run agrees to 1.31e-15 m/s.
Both reference runs close their reported energy balance and have nonnegative bristle dissipation in this particular example; the discrepancy does not demonstrate a passivity violation for that run.
Against the unchanged author output, the correction produces 0.0276 relative waveform L2 difference, 0.401 dB active-bin short-time spectral RMSE, and 0.000495 relative RMS-envelope difference.

## Equations and validation

`Evaluate` implements the adhesion map and steady bristle displacement in Equations 6–9, the refined damping in Equation 14, and the bristle evolution in Equation 24, with the published exponent `p=2`.
The refined damping is `muC * normal_force / sqrt(v² + epsilon²)`, where `epsilon = muC * normal_force / nominal_damping`.
Its dissipation is evaluated independently as `v * friction_force - stiffness * midpoint_bristle * bristle_rate`.
Zero nominal damping is supported directly.
Normal force must remain positive; lifting the bow requires an additional contact/separation model.

`Step` implements Equations 52–61 with simply supported transverse ends, fixed torsional ends, central string differences, averaged bow-hair stiffness, and interleaved bristle displacement.
The nonlinear velocity/bristle system uses an analytic Jacobian with pivoted elimination and the author's 1.1 Jacobian scaling after iteration 50.
FP64 convergence requires a residual below 2e-13 and fails explicitly at 100 updates.
Stored string, torsional, hair, and bristle energies are calculated independently from the state using Section 6.3.
Dissipation and external work are integrated to test the complete energy balance, including a nonzero initial state.
The frequency-dependent string-loss term follows the paper's stated discrete energy bookkeeping; the specifically guaranteed local passivity check is the bristle dissipation.

Tests cover independent CFL bounds, finite-difference derivatives, elastic and steady-slip limits, a high-damping friction passivity grid, full-record author bridge/velocity/energy comparison, nonzero initial-state energy conservation, lumped energy conservation, and CPU/Metal trajectories.
The full 0.5 s corrected author bridge matches FP64 C++ to a maximum absolute error of 7.88e-11 N and relative L2 error of 3.73e-12.
The complete energy error is below 4.4e-14 J in that run.
Author energy is sampled before each update; native reported energy is sampled after the update, and the test accounts for this difference.

## Metal workload and accuracy

`RenderStringsGpu` runs the complete distributed model with up to eight contacts per string.
Each GPU thread advances one trajectory, preserving the time dependency and Newton iteration within that trajectory.
The GPU analytically eliminates the diagonal bristle block before solving an M-by-M slip system, then reconstructs the bristle update; cubic interpolation evaluates only its four nonzero coefficients.
The output includes failed-step counts, maximum nonlinear residual, and final state; FP32 is not treated as a machine-precision passivity certificate.
The FP64 CPU reference completes small batches sooner in these measurements.
Clang 23.1.0 vectorization remarks confirm two-wide FP64 SIMD in interpolation reductions, Jacobian elimination, force spreading, and state updates.
`RenderLumpedGpu` provides an additional parallel workload for the bowed-mass system in Equations 25–35 using Table 1 parameters.

The full distributed kernel was measured on Apple M5 Max with Release Clang 23.1.0 using 128 voices, 22050 frames per voice, and normal forces `2.3433f * (1 + 0.0001f * voice)`.
Three fresh-process runs measured 4.04–7.95 s for the FP32 GPU renderer and 7.40–7.89 s for the FP64 CPU reference.
For one voice with the same 0.5 s duration, the GPU took 2.85 s and the CPU reference took 0.0566 s, so the GPU path is an ensemble renderer with substantial per-trajectory latency.
Both use identical float-rounded controls.
The CPU elapsed time includes its independent full energy accounting, while the GPU reports nonlinear residuals and final state and omits that global energy calculation.
GPU timing includes kernel creation, allocation, upload, dispatch, completion, and readback; CPU timing includes state construction and full trajectory generation and excludes comparison reductions.
These elapsed times describe different precision and diagnostic workloads and are not an equivalent-workload speedup comparison.

Aggregate waveform relative L2 error was 2.51e-4, worst-voice relative L2 error 5.61e-4, and maximum force error 0.00953 N.
Final transverse-displacement, torsional-displacement, bristle-displacement, and slip-velocity relative L2 errors were 9.07e-5, 8.59e-4, 6.30e-4, and 0.00507 respectively.
All steps converged below the FP32 residual threshold of 2e-6.
These are measured trajectory differences for this workload, not a general precision or real-time guarantee; chaotic bowing regimes and other parameters require their own checks.
Each reproduction manifest records its run’s timings and errors.

## Audio scope

The official [fast sautillé example](https://www.mdw.ac.at/upload/MDWeb/iwk/mp3/FastSautille.mp3) is downloaded and decoded as `author_fast_sautille.wav` when FFmpeg is available.
It remains a separate author listening reference.
The paper says this example uses periodic time-varying bow force/velocity and convolution with a measured cello impulse response, but the archived implementation supplies neither those drive trajectories nor that impulse response.
Consequently, the matched reproduction is the openly supplied 0.5 s bridge-force computation, not the sautillé recording.
The manifest reports waveform, short-time spectrum, RMS-envelope, and shared texture measurements for comparable signals without fitting missing excitation or body-filter parameters.
